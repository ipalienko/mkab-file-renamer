# MKAB File Renamer

PowerShell-утилита для автоматического сопоставления медицинских файлов с пациентами в Microsoft SQL Server и безопасного добавления `MKABID` в начало имени файла.

Проект предназначен для каталогов, куда диагностические системы или сотрудники складывают `.pdf`, `.doc` и `.docx` файлы с ФИО пациента. Скрипт сначала пытается определить пациента по имени файла. Если этого недостаточно, он читает содержимое документа, извлекает ФИО, дату рождения и номер карты, сверяет данные с `dbo.hlt_MKAB` и переименовывает файл только при достаточно надёжном совпадении.

> **Важно:** репозиторий не содержит рабочих паролей, адресов серверов и путей конкретной организации. Локальные параметры хранятся в `config.json`, который исключён через `.gitignore`.

## Возможности

- рекурсивный обход сетевой папки;
- обработка `.pdf`, `.doc` и `.docx`;
- PDF разбираются через `pdftotext` из Poppler;
- DOC/DOCX читаются через Microsoft Word COM;
- поиск пациента по фамилии, имени/инициалам и отчеству;
- уточнение по дате рождения;
- использование `Номер карты`/`MKABID` с дополнительной проверкой ФИО;
- осторожная обработка небольших опечаток в ФИО при наличии сильных идентификаторов;
- блокировка конфликтов, когда номер карты и ФИО указывают на разных пациентов;
- режим Preview без изменения файлов;
- CSV-журнал каждого запуска;
- lock-файл от параллельных запусков;
- очистка старых журналов;
- работа через Windows Task Scheduler.

## Требуемая структура БД

По умолчанию скрипт работает с таблицей:

```sql
dbo.hlt_MKAB
```

и ожидает поля:

| Поле | Назначение |
|---|---|
| `MKABID` | уникальный номер медицинской карты / идентификатор пациента |
| `FAMILY` | фамилия |
| `NAME` | имя |
| `OT` | отчество |
| `DATE_BD` | дата рождения |

Если ваша схема отличается, измените SQL-запросы в `Rename-FilesByMkab.ps1`.

Для работы достаточно SQL-пользователя с правом `SELECT` на эту таблицу. Не используйте в конфигурации учётную запись с правами изменения данных, если в этом нет отдельной необходимости.

## Компоненты

### Обязательно

1. **Windows PowerShell 5.1**  
   Скрипт рассчитан на стандартный Windows PowerShell, присутствующий в Windows 10/11 и Windows Server.

2. **Microsoft Word Desktop, версия 16.x или совместимая**  
   Используется для извлечения текста из старых `.doc` и современных `.docx`.

3. **Poppler for Windows / `pdftotext.exe`**  
   Используется для корректного извлечения текста из PDF с сохранением расположения строк. Подойдёт, например, Windows-сборка Poppler:  
   <https://github.com/oschwartz10612/poppler-windows/releases>

4. **Microsoft SQL Server**  
   Сервер должен быть доступен с компьютера, на котором запускается скрипт.

5. **Доступ к SMB/сетевой папке**  
   Учётная запись запуска должна иметь как минимум чтение каталога и право переименования/изменения файлов.

### Для автоматического запуска

- Windows Task Scheduler;
- доменная или локальная служебная учётная запись;
- право **Log on as a batch job** (`SeBatchLogonRight`);
- отсутствие этой учётной записи в **Deny log on as a batch job**;
- сохранённый пароль задачи (`LogonType Password`), если используется сетевой SMB-ресурс.

## Установка

### 1. Скопировать проект

```powershell
git clone https://github.com/ipalienko/mkab-file-renamer.git
cd mkab-file-renamer
```

Либо скачайте ZIP и распакуйте, например, в:

```text
C:\Scripts\MKAB-File-Renamer
```

### 2. Установить Poppler

Распакуйте Poppler так, чтобы файл находился, например, здесь:

```text
C:\Scripts\MKAB-File-Renamer\tools\poppler\bin\pdftotext.exe
```

Каталог `tools/` намеренно не хранится в Git.

Проверка:

```powershell
& ".\tools\poppler\bin\pdftotext.exe" -v
```

### 3. Установить Microsoft Word

Проверьте COM-автоматизацию под той учётной записью, от которой будет запускаться задача:

```powershell
$word = New-Object -ComObject Word.Application
$word.Version
$word.Quit()
```

### 4. Создать локальный config.json

Скопируйте шаблон:

```powershell
Copy-Item .\config.example.json .\config.json
```

Заполните `config.json` своими параметрами:

```json
{
  "Sql": {
    "Server": "sql-server.example.local",
    "Database": "medical_database",
    "User": "readonly_user",
    "Password": "CHANGE_ME",
    "Encrypt": false,
    "TrustServerCertificate": true
  },
  "Share": {
    "Root": "\\\\fileserver\\share\\incoming"
  },
  "Tools": {
    "PdfToText": ".\\tools\\poppler\\bin\\pdftotext.exe"
  }
}
```

`config.json` находится в `.gitignore`, поэтому рабочие пароли не должны попасть в репозиторий.

Рекомендуется ограничить NTFS-доступ к `config.json` только администраторам и учётной записи, которая запускает скрипт.

### 5. Проверить зависимости

```powershell
powershell.exe -ExecutionPolicy Bypass -File .\Test-Prerequisites.ps1
```

Проверяются:

- доступ к сетевой папке;
- наличие `pdftotext.exe`;
- запуск Microsoft Word COM;
- подключение к SQL Server;
- чтение `dbo.hlt_MKAB`.

### 6. Проверить синтаксис

Запустите:

```text
Check-Syntax.cmd
```

Ожидаемый результат:

```text
PowerShell syntax: OK
```

### 7. Первый запуск — только Preview

```text
Run-Preview.cmd
```

Preview ничего не переименовывает. В `logs/` появится CSV вида:

```text
preview_v6_YYYYMMDD_HHMMSS.csv
```

Перед реальным запуском обязательно просмотрите строки со статусами конфликтов и неоднозначного определения пациента.

### 8. Реальное переименование

После проверки Preview:

```text
Run-Apply.cmd
```

Файл получает имя вида:

```text
1234567 Исходное имя.pdf
```

где `1234567` — подтверждённый `MKABID`.

## Как определяется пациент

Упрощённый порядок:

1. Разобрать ФИО/инициалы из имени файла.
2. Если найден один пациент — использовать его.
3. Если совпадений нет или их несколько — прочитать документ.
4. Извлечь возможные признаки:
   - `ФИО:`;
   - `Пациент:`;
   - `Дата рождения:` / `Дата рожд.:`;
   - `Номер карты:`;
   - распространённые форматы диагностических отчётов.
5. Проверить `Номер карты` как `MKABID` в SQL.
6. Сверить номер карты с ФИО и, при наличии, датой рождения.
7. Если номер карты отсутствует или не существует — попытаться найти пациента по ФИО + дате рождения.
8. При конфликте сильных идентификаторов файл **не переименовывается автоматически**.

Небольшая опечатка может быть принята только при наличии дополнительных подтверждающих данных. Логика специально настроена консервативно: лучше оставить файл необработанным, чем присвоить его не тому пациенту.

## Логи

По умолчанию журналы создаются в:

```text
logs\
```

CSV содержит исходное имя, разобранное ФИО, данные из содержимого, найденный MKABID, источник сопоставления, итоговый статус и пояснения.

Срок хранения задаётся:

```json
"LogRetentionDays": 90
```

## Автоматический запуск через Task Scheduler

Для установки ежедневной задачи от имени служебной учётной записи откройте PowerShell **от администратора**:

```powershell
.\Install-ScheduledTask.ps1 -RunAsUser "DOMAIN\\service-account" -DailyAt "03:00"
```

Скрипт запросит пароль интерактивно и не сохраняет его в исходных файлах проекта.

После установки проверьте:

```powershell
Start-ScheduledTask -TaskName "MKAB File Renamer"
Start-Sleep -Seconds 15
Get-ScheduledTaskInfo -TaskName "MKAB File Renamer" |
    Format-List LastRunTime, LastTaskResult, NextRunTime
```

Успешный запуск:

```text
LastTaskResult : 0
```

Если возникает `0x80070569`, учётной записи обычно не выдано право **Log on as a batch job**.

## Права на файлы

Учётной записи автоматического запуска обычно нужны:

- `Read & Execute` на каталог проекта;
- `Modify` на `logs/`;
- `Modify` на обрабатываемую сетевую папку;
- доступ к SQL Server под логином из `config.json`.

## Безопасность

- Не коммитьте `config.json`.
- Используйте отдельного SQL-пользователя только для чтения.
- Ограничьте NTFS-доступ к конфигурации.
- Всегда выполняйте Preview после изменения правил сопоставления.
- Не отключайте защиту конфликтов ради увеличения процента автоматического распознавания.
- Не помещайте реальные медицинские документы и CSV-журналы в публичный репозиторий: они могут содержать персональные данные.

## Ограничения

- PDF без текстового слоя (сканы) не распознаются OCR-механизмом.
- Для `.doc`/`.docx` требуется установленный desktop Microsoft Word.
- SQL-схема `dbo.hlt_MKAB` является частью текущей реализации.
- Автоматическая обработка должна запускаться только после тестирования на ваших реальных шаблонах документов.
